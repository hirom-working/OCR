# スキャナー × AI：スキャンした書類を「本当に使える」デジタル資産へ

スキャナーで取り込んだPDF、そのまま眠っていませんか？
最新のAI技術（OCRと大規模言語モデル）を組み合わせ、スキャン後の「文字埋め込み・整理・リネーム」を完全自動化するツールを作成しました。

---

## 1. 課題：スキャンPDFの悩み

「紙をなくしてスッキリしたい」と思ってスキャナーを買ったものの、こんな悩みを持っていませんか？

- **中身が検索できない**：ただの「画像」として保存されるため、後からキーワードで探せない
- **ファイル名が適当**：「Scan_20240121.pdf」のような名前になり、中身を開くまで何かわからない
- **整理が面倒**：スキャンした後に手動で名前を変えたり、フォルダ分けするのが大変で、結局「取り込みフォルダ」に溜まったまま

---

## 2. 解決策：OCR + LLMで全自動化

このツールを使えば、**スキャンして待つだけ**で面倒な作業がすべて完了します。

- **全文検索に対応**：高精度なOCR（文字認識）で、PDF内の文字を検索可能にします
- **自動リネーム**：AIが内容を読み取り、「[夏目漱石] こころ.pdf」のように適切なファイル名を自動で付けます
- **自動整理**：処理が終わったファイルは、指定した「電子図書」フォルダへ自動的に移動します

---

## 3. 仕組み：処理の流れ

PCの裏側では、以下のようなリレー形式で処理が行われます。

### フロー図

```
┌─────────────┐
│  スキャン   │  スキャナーでPDFを作成
└─────┬───────┘
      ↓
┌─────────────┐
│  フォルダ   │  ~/Scansnap に保存
│    監視     │  （自動検知）
└─────┬───────┘
      ↓
┌─────────────┐
│    OCR      │  GPUサーバーで文字認識
│  (Surya)    │  （高速・高精度）
└─────┬───────┘
      ↓
┌─────────────┐
│  テキスト   │  読み取った文字を
│   埋め込み  │  PDFに透明レイヤーで追加
└─────┬───────┘
      ↓
┌─────────────┐
│    LLM      │  タイトル・著者を
│  (Ollama)   │  AIが自動推測
└─────┬───────┘
      ↓
┌─────────────┐
│  リネーム   │  [著者] タイトル.pdf
│   & 移動    │  → ~/電子図書/ へ
└─────────────┘
```

### 各ステップの詳細

1. **検知**: スキャンフォルダにPDFが入ると自動でスタート
2. **OCR（文字認識）**: GPUサーバーに送り、Suryaエンジンで文字を読み取り
3. **テキスト埋め込み**: 読み取った文字情報をPDFに埋め込み、検索可能に
4. **情報抽出**: LLMが本文を読み、タイトルと著者を推測
5. **リネーム**: `[著者] タイトル.pdf` または `タイトル.pdf` に名前を変更
6. **整理**: 完成したファイルを出力フォルダへ移動し、作業用ファイルを削除

## 4. こだわりポイント

### 高精度OCR「Surya」の採用

従来のOCRソフト（Tesseract等）よりもレイアウト認識に優れ、日本語を含む多言語に対応した最新のAIモデルです。GPUを使うことで高速かつ正確に文字をデータ化します。

### LLMによる「文脈」理解

単に一行目をファイル名にするのではなく、LLM（大規模言語モデル）が文書の冒頭やメタデータを読み、「何がタイトルで、誰が著者か」を人間のように判断します。

### 環境に依存しない設計

設定ファイル（`config.toml`）を書き換えるだけで、サーバー構成やフォルダパスが変わっても柔軟に対応できます。別の環境への移植も容易です。

## 5. 必要なもの・始め方

### 必要な環境

| 項目 | 説明 | 必須 |
|------|------|:----:|
| スキャナー | ScanSnap等、PDF保存できるもの | ○ |
| ホストPC | Mac または Linux | ○ |
| Python 3.11以上 | スクリプト実行環境 | ○ |
| GPUサーバー | NVIDIA GPU搭載マシン（SSH接続） | △ |
| Ollamaサーバー | LLMを動かす環境 | △ |

> **注**: GPUサーバーがなくてもCPUで動作しますが、処理速度が大幅に低下します。
> GPUサーバーとOllamaサーバーは同一マシンでも構いません。

### セットアップ手順

```bash
# 1. リポジトリをクローン
git clone https://github.com/yourname/ocr-pipeline.git
cd ocr-pipeline

# 2. Python環境をセットアップ（uvを使用）
uv sync

# 3. 設定ファイルを作成
cp config.example.toml config.toml
# config.toml を編集してサーバー情報を設定

# 4. 監視を開始
uv run python watch_scansnap.py
```

あとはスキャナーでスキャンするだけです。

### 手動実行（単発処理）

```bash
# 特定のPDFを処理
uv run python process_pdf.py /path/to/document.pdf

# フォルダ内の全PDFをバッチ処理
uv run python pipeline.py /path/to/pdfs/
```
